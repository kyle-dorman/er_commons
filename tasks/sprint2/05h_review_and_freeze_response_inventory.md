The new question is whether composition and display faithfully preserve source

Deduplicate subjects while retaining all selection reasons and obligations.
`warning_profile` is the sorted set of warning codes/coverage kinds, excluding
free text, timestamps and IDs; exclude IDs from stratum keys to avoid accidental
per-row strata. No random sample or unrecorded ad hoc substitution. A class card
is a reviewed rule-level decision only if exact membership shares the same
accepted rule and reason; heterogeneous cases split into explicit subclasses.
A sampled view proves only that view. Machine all-row closure and inherited
coverage remain independently reported.

Use a simple read-only, lazy text view extending the established 05E view
pattern: comment, direct response, referenced response/General Response,
original anchor, directed edge evidence, raw mention, accepted target identity,
nonlink reason and all limitations. Keep original unit boundaries and ordering.
No auto-following cycles or flattening linked answers. Use a small explicit
review ledger rather than build another application/questionnaire. The curator
may mark `confirmed_composition`, `confirmed_with_limitation` or
`correction_required`, with rationale and exact evidence references. The agent
may prepare/check records, but may not invent the user's human judgments.

On a sample mismatch, mark its entire affected stratum pending, preserve the
finding and propose a bounded amendment or complete-stratum review. Stop before
acceptance; no automatic extrapolation or expansion of source access. If text
cannot resolve a source-fidelity question, stop that item for separately
approved visual evidence. Accepted upstream populations are not automatically
reopened by a display bug.

## Commands, implementation boundary and resource limits

The following interfaces are implemented. Production commands remain disabled
pending their separate authorization gates. Use the isolated `er-responses` CLI with
small `release_spec`, `release_review`, `release_validation` and
`release_publication` responsibilities. Reuse generic artifact I/O deliberately;
do not invoke accepted producer/resolver workflows merely to load records.

```text
make validate-response-inventory-contract
uv run er-responses validate-spec --run-spec <05h-request>
uv run er-responses prepare-05h --run-spec <05h-request> --attempt <N>
uv run er-responses review-05h --run-spec <05h-request> --attempt <N>
uv run er-responses validate-05h --run-spec <05h-request> --attempt <N> --candidate-root <working-candidate>
uv run er-responses finalize-05h --run-spec <05h-request> --attempt <N>
uv run er-responses publish-05h --run-spec <publication-request> --attempt <N> --candidate-root <finalized-candidate>
uv run er-responses accept-05h --run-spec <acceptance-request> --attempt <N> --candidate-root <published-inventory> --accepted-by <reviewer> --accepted-at <timestamp>
```

`prepare` composes references/checks and materializes the frozen selection;
`review` writes the regenerable text-view cache only, not decisions. Curator
ledger entry is explicit. `validate` is read-only and returns actionable subject,
path and invariant failures. `finalize` requires closed review and current
quality/validation reports. `publish` makes the no-clobber final release only;
`accept` separately designates it after successful terminal supervision. Concrete
request paths, exact runtime owner list/digests and supervisor commands are bound
in the Phase 2 execution packet below. Add Make wrappers if routine execution
benefits; preserve historical requests and central document CLI behavior.

For production preparation, composition, cache building, finalization and
publication use the existing background resource supervisor: one worker, two
CPU threads, 4 GiB process-tree RSS, zero swap growth, 1,800 active seconds per
command, 8 GiB free-space minimum, and 2 GiB cumulative **new 05H output** across
all attempts, staging, caches, logs and final publication. No network or model
calls. Human reading time is excluded from command deadlines. Limits are
conservative ceilings based on the small 05D/05E records and accepted 05G's
sub-1-GiB RSS, not claimed new measurements. Estimate actual full output before
launch; stop if it cannot fit, including both staging and final retained bytes.
Any cap increase or added read population needs a reviewed amendment. Repository
fixture checks are separate from this production execution budget.

## Restart, finalization and downstream gates

checkpoint last. Reuse only explicitly named same-plan checkpoints with matching

closed, no conflicting decisions, repeatable semantic records, retained

supports only its declared question and coverage; none substitutes for the others.
