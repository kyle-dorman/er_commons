## Abstract

contract as thin project-owned glue over the Task 03E.2d-accepted corrected
hierarchy. Combine the changed v2 definitions with the otherwise unchanged v1
record families and publish a new immutable Appendix P canonical candidate.
The candidate extends existing section and content records, emits one printed-
page-label observation per physical page, adds deterministic target aliases,
and records exact correspondence to the Task 03D.1 core records.

The RFC 8785 plus SHA-256 extraction-ID algorithm and `exv1-` prefix remain
unchanged, but the expanded identity payload must produce a candidate ID
different from the Task 03D.1 candidate. Task 03E.3 defined the identity and
bridge policies and verified their real handoff facts; it did not publish a
candidate identity or candidate-owned bridge artifact.

Visible TOCs and the PDF outline carry Task 03E.2d-accepted reconciliation
evidence and support validation and aliases. The accompanying bounded-
acceptance record remains visible provenance. These inputs do not authorize new
materialization-local hierarchy inference.

The first implementation proved behavior and produced a visually approved MVP,
but it does not meet the repository's human-ownership standard. This task now
includes a required source rewrite. The MVP candidate remains immutable
reference evidence; implementation structure, not semantic behavior, is the
only authorized change.

`exv1-c500c1731aa02a97d3cebe1b582eb8b03671a75b29eb3f1df349edd2f34fe5bf`

Use a functional-core and orchestration-shell shape: frozen dataclasses name
verified inputs and meaningful intermediate results; small builders own one
record/evidence relationship; persisted records remain plain dictionaries under
the accepted JSON Schema; and file-system publication remains an explicit edge.
PEP 8's central maintenance lesson is that code is read more often than it is
written and that local project consistency matters most
(<https://peps.python.org/pep-0008/>). Python modules supply a clear namespace
boundary without requiring a framework
(<https://docs.python.org/3/tutorial/modules.html>). Therefore this rewrite
will use cohesive modules and named typed values, not a generic workflow,
plugin registry, dependency-injection container, inheritance hierarchy, or
compatibility facade.

1. Freeze the MVP candidate's complete candidate-owned file map and semantic
   projection before changing runtime code. Verify its completion, inventory,
