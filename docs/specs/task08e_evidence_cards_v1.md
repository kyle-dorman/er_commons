# Task08E evidence cards v1

The user requested a single reading order for each evidence item: **E01 → Summary
→ Why retrieved → Parsed source → Relationship to E01**. The prior split layout
made the reviewer move between distant notes, sources and controls.

## Bounded plan

1. Snapshot the current project, saved annotations and drafts before changing it.
2. Add a shared, named card-layout revision. Derive each card from its existing
   candidate and alias; keep the complete source, warnings and provenance with
   that item. Use one page scroll, with no independently scrolling source column.
3. Preserve every native decision control name, option and evidence association.
   Keep the old form executable for historical exports. Qualify the new form with
   separate synthetic save/edit/reload/export checks and inspect actual cards.
4. Apply the layout to the live project only after preserving prior snapshots and
   checking that saved decisions have not changed. Record old/new presentation
   bindings; source packets, approved claims, question scope and chains stay exact.
5. Verify the live queue, update its current routing and return its review link.

The summary is the existing advisory proposal, not source text or a human choice.
Warnings remain attached to their own card; detailed canonical provenance can be
collapsed there. Claim-wide outcome and notes follow the cards. Original comment,
response context and unresolved scope remain accessible without repeating them
inside every card. No new source discovery, eligibility decision or 08F work is
part of this revision.

Native control identity remains the compatibility boundary: rearranging controls
must not change which source a saved relationship describes. Existing source and
packet validators still run against the same canonical artifacts. The three
historical Task06G commit-pin failures remain carried forward.

Applied to the existing project 59 after independent synthetic project 60 proved
save/edit/reload/export and draft retention. All 20 task IDs, exact source packets
and the existing human draft remain preserved. Live browser checks verified one,

binds prepared tasks, migration receipts, browser verification and validation.
The prior form remains replayable. Human evidence and eligibility review remain
