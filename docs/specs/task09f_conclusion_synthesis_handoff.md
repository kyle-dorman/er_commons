## Exact judge-visible fields

Each input has only `question`, `candidate_conclusion`, and
`reference_conclusion`, all strings. Use the approved conclusion's text, preserving
its list formatting; do not pass its citation IDs or other reference fields.
No supporting points, qualifications outside the conclusion field, source passages,
reference explanation, expected label, perturbation ID or rationale reaches C.

If the reference conclusion is insufficient to determine a required condition or
item without consulting other reference fields, flag the slot/case as ambiguous.
Do not silently enrich this input contract or repair the approved reference.

## Authoring allocation

Use one example per applicable row of the filtered passing/failing tables, plus
one unchanged reference conclusion per question. The combined P03/P04 row is one
slot; the combined F05/F09 row is one slot. Do not split these into multiple edits.

There are 20 mutation slots plus the unchanged control per question: at most 399
records across 19 questions if all slots apply. This is a ceiling, not a quota.
Every slot must be accounted for as generated, inapplicable, or unresolved. Record
why; do not force unnatural changes or force a positive/negative class ratio.

Keep overlapping category lineage explicit. Flag duplicate candidates; one candidate
may cover multiple applicable slots via explicit shared-ID coverage rather than
being counted twice as an independent example. Each slot maps to at most one
accepted candidate. Preserve rejected/revised drafts separately when relevant.

Do not generate support-independence variants, clean abstentions, malformed outputs
or prompt-injection tests in this semantic batch. For O04 use a nonresponsive
conclusion, not a clean insufficient-evidence abstention. Apply list-specific
categories only where appropriate. Numerical and condition changes must be
material to the approved answer, not merely different from an optional detail.

non-overlapping development cases and independently review them. No provider API,
external generation service or judge execution; no credential access is needed.

Use existing validation and artifact I/O where applicable. Write fresh versioned
artifacts under ER_COMMONS_DATA_ROOT, following the artifact contract. Bind exact
release, rules, catalog and authoring instructions. Do not alter previous data.

Manifest mappings must reconnect payloads and labels without leaking labels into
payloads. Retain unresolved labels explicitly; do not manufacture booleans.
